# Ayre Scanner — Redesign Implementation Report

Implementation of `ayrescan_final.md`. The engineering foundation was kept as
specified; the visual surface, the way data is drawn, and the information
architecture were rebuilt.

**Verification:** `flutter analyze` → 0 issues · `flutter test` → 25/25 pass ·
`flutter build web --release` → succeeds. Run against Flutter 3.44.9 / Dart 3.12.2.

## 3. Design system

**Colour.** Warm brass `primary` is the sole brand hue. The base is warm at
every step in both themes — parchment in light, warm ink-graphite in dark, never
blue-tinted black. Light and dark were tuned separately against their own
backgrounds rather than numerically inverted. `accentCool` is a cartographic
slate that reads as ink; `accentWarm` ("ember") is confined to the four
sanctioned uses; `accentMint` moved out of the teal/green family entirely
(muted plum) so it can't drift back toward reading as a paler brand colour.
Added `primaryMuted` for large hero fills, plus `hairline` and `engraved` for
the line-work; removed every `shadow`/`paper` token — elevation now reads
through lightness and warmth, and there are no drop shadows in the system.

**Typography.** Three roles, no fourth treatment anywhere:

- **IBM Plex Mono** with tabular figures — every live market figure, the gauge
  reading, every freshness timestamp. Routed through the `Numeral` widget so a
  screen *cannot* fall back to Inter for a price.
- **Fraunces** — screen titles, section eyebrows, headings; and a numeral in
  exactly two places (Home's momentum score, the splash wordmark).
- **Inter** — body copy, list-row labels, buttons, all-caps categorical
  micro-labels.

**Shape.** Radii roughly halved (card 18→10, hero 24→12, xl 28→14). The
full-pill shape retired as a default, surviving only for small chips and — by
design — the nav bar. `ChamferedBorder` added as the second, controlled voice,
used on the gauge housing.

**Motion.** The no-bounce policy is kept exactly as strict. Added
critically-damped springs (ratio 1.0) via `SpringValue`, which re-targets from
current position *and velocity* when interrupted; `AppMotion.choreographed`
(600ms); the needle sweep; a mechanical digit-roll; the sliding needle-mark with
an 18ms lag behind the label reveal; and one reusable live-data pulse that plays
once and never loops. Every one of these collapses to an instant swap under
reduced motion.

**Ornament.** Every glow, blob and gradient sweep deleted — `AuraHalo`,
`FloatingOrb`, `_BlurCircle`, `_AmbientShapes`, all of `AppGradients`, and
Splash's rotating gradient ring. Replaced by `TickMarks`, `ContourLines` and
`BearingMark`, used at most once per screen: Home's hero has one, Signals and
Learn have none, Login and Splash share the bearing mark. The only gradient left
in the app shades the dial face.

## 4. Data drawn as instrument readings

The gauge was rebuilt, not recoloured: a near-semicircular dial with 41 engraved
calibration ticks, a fine index needle with a counterweight tail and hub, and
the reading in monospace. The needle sweeps on a spring from the old value to
the new one. The weekly/monthly toggle, the underlying data, and the
deliberately calm static error state are unchanged.

The sparkline is now a hairline trace with a tick baseline — straight segments,
not eased curves, because an instrument records what happened rather than
smoothing it. The filled gradient area is gone. Its default stroke is brass, not
a gain/loss colour; direction is carried by the sign and glyph beside it. On a
data change it morphs progressively, re-targeting mid-flight.

## 5. Home's three new market-data sections

`MarketMoversService` is the only dependency the new widgets have — no widget
touches an HTTP client or URL. Sorting is per spec (gainers descending, losers
most-negative first, most-active by volume). A row missing any always-required
field is dropped; a section missing optional data degrades that piece of UI only.

All six states are implemented and tested: skeleton loading, loaded, empty,
error, stale (last-known values kept, flagged with ember and explicit copy), and
refresh. A failed "Most Active" fetch is scoped to its own section and does not
block the rest of Home.

Rows are non-interactive: there is no stock-detail or trading surface for them
to lead to, and inventing one to give the row a destination would be worse.

## 6. Decisions worth flagging

These are places where following the spec's own rules meant *not* building
something it sketched. Each is a judgment call you may want to reverse.

1. **Settings ships three notification toggles, but not the original three.**
   The spec says to migrate the existing toggles, but also that no row should
   ship unless it maps to working behaviour. Push delivery, watchlist price
   alerts and a weekly digest have no backing capability, so shipping them would
   have recreated problem #2 inside the new screen. They are replaced by three
   toggles that genuinely gate what the alerts log records: in-app alerts (the
   master), new-signal alerts, and delayed-data warnings.

2. **The bell's list is generated locally.** The spec says the list should come
   from "what the existing alert/digest settings already generate", but no
   backend endpoint produces it. Entries are recorded from real events — a
   scanner pick you hadn't seen, a provider falling behind — persisted, and
   gated by the toggles above. A fresh install correctly shows the empty state.

3. **Edit Profile edits one field.** The backend exposes session identity but no
   profile-update endpoint, so the display name is stored on-device and the
   username is shown read-only rather than as a field that would silently fail
   to save.

4. **`MarketMoversService`'s implementation points at `/api/market/gainers`,
   `/losers` and `/most-active`.** Per §8 the spec doesn't pick a provider, so I
   put the decision on the server where it can change without an app release.
   **These three endpoints do not exist yet** — until they do, the sections
   render their error state, which is why that state is tested. Swapping in a
   different source means implementing the interface; no widget changes.

5. **App version is a constant** in `support_screen.dart` rather than read at
   runtime, to avoid adding a plugin dependency for a version string. It needs
   bumping alongside `pubspec.yaml`.

6. **Lesson cards now push a reader screen.** The card's arrow affordance
   implied navigation and previously did nothing; the lesson body was already
   being truncated in the card, so the reader shows real content.

## 7. Not done

- **APCA re-verification of dark-theme pairings** (P2 #28). WCAG AA is enforced
  by test in both themes; APCA needs a tool this repo doesn't have.
- **"See all" full-list screens** for the mover sections (P2 #27) — the spec
  marks these as only-if-needed, and the fixed 3–5 rows may prove sufficient.
- **Per-row micro-sparklines** (P2 #26) — explicitly not required for v1, and
  the data source doesn't yet return enough points per row.

## 8. Test coverage added

`test/widget_test.dart` — brass-hue and warm-base assertions across both themes;
a WCAG contrast calculation proving all three text tones clear 4.5:1 (the check
problem #7 failed); tabular-figure and monospace enforcement; formatter
behaviour.

`test/render_smoke_test.dart` — 19 render tests: the gauge painting and
re-targeting mid-sweep in both themes, sparkline morphing, all engraved marks
and the chamfer, the digit-roll, delta redundant encoding, all five
mover-section states, every pushed screen, Save-disabled-until-dirty, the
five-tab shell with tab switching, the wide-viewport side rail, the live pulse,
and reduced motion.

One production change was made for testability: `navSegmentKey(label)` in
`home_shell.dart` gives each nav destination a stable handle, since inactive
segments are icon-only and have no label text to address them by.
